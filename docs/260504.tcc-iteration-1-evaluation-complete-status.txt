--------------------------------------------------------------------------------
2.1 SIX FAILURE MODE CATEGORIES
--------------------------------------------------------------------------------

FailureModeEnum defines seven values. Value 0 is Error (uninitialized sentinel
per standard-enum-zero-is-error.txt). The six real categories are:

    FailureModeEnum value          Constraint type        Tile triggers check
    -----------------------------  ---------------------  --------------------
    BrokenPipeHorizontal           Local adjacency        PipeBodyLeft
    BrokenPipeTopLeft              Local adjacency        PipeTopLeft
    BrokenPipeTopRight             Local adjacency        PipeTopRight
    BrokenBulletBill               Local adjacency        BulletBillLauncher
    FloatingEnemy                  Gravity/support        Enemy
    DiscontinuousGround            Global structural      Bottom-row Empty

--------------------------------------------------------------------------------
2.2 PER-METHOD CHECK LOGIC
--------------------------------------------------------------------------------

Each Check method follows an identical pattern: nested for loops scan every
tile, the method only acts when it finds its trigger tile type, then it
inspects a specific neighbor and emits a FailureModeViolation if the
constraint fails.

    CheckBrokenPipeHorizontal:
        For every PipeBodyLeft, the tile at (x+1, y) must be PipeBodyRight.

    CheckBrokenPipeTopLeft:
        For every PipeTopLeft, the tile at (x, y+1) must be PipeBodyLeft.

    CheckBrokenPipeTopRight:
        For every PipeTopRight, the tile at (x, y+1) must be PipeBodyRight.

    CheckBrokenBulletBill:
        For every BulletBillLauncher, the tile at (x, y+1) must be
        BulletBillBody.

    CheckFloatingEnemy:
        For every Enemy tile, the tile at (x, y+1) must be Solid, Breakable,
        QuestionFull, or QuestionEmpty. Enemies on the bottom row (y =
        Height-1) are treated as implicitly supported by the ground edge.

    CheckDiscontinuousGround:
        For every tile at y = Height-1, if the tile is Empty it counts as
        a gap. Each Empty in the bottom row produces one violation.

--------------------------------------------------------------------------------
2.3 RESULT AGGREGATION CONTRACT
--------------------------------------------------------------------------------

FailureModeAnalysisResult exposes both fine-grained and coarse-grained data:

    Field                          Type                              Meaning
    -----------------------------  --------------------------------  -------
    Violations                     List<FailureModeViolation>        All violations, with X, Y, Mode
    TotalViolations                int                               Convenience: equals Violations.Count
    BrokenPipeHorizontalCount      int                               Per-type tally
    BrokenPipeTopLeftCount         int                               Per-type tally
    BrokenPipeTopRightCount        int                               Per-type tally
    BrokenBulletBillCount          int                               Per-type tally
    FloatingEnemyCount             int                               Per-type tally
    DiscontinuousGroundCount       int                               Per-type tally
    TotalTiles                     int                               Width times Height
    ViolationRate                  double                            TotalViolations / TotalTiles

CONTRACT INVARIANT: TotalViolations equals Violations.Count, and equals the
sum of all per-type counts. This invariant is now enforced by an aggregate
integrity test.

PART 5: PROF. ELDER CONVERSATION 2026-05-04
================================================================================

On 2026-05-04 Prof. Elder Rizzon Santos responded by audio to the question
about qualitative evaluation direction. His instructions (transcribed and
paraphrased):

    "Acho que as duas opções que tu colocou são boas. O que eu pensei
    inicialmente, considerando mapa/fase, seria verificar se é um cenário
    possível ou impossível, se tem um fim no local esperado, se a quantidade
    de obstáculos ta ok. Essa ideia da inspeção visual pode ser interessante,
    só que tem a limitação de que tu ta avaliando pela semelhança, nem tanto
    pela diferença, mas funciona. Acho que o item 2 acaba sendo mais
    interessante pro teu TCC, mas o item 1 também é bem legal. Se tiver
    tempo pode fazer ambos, mas começa pelo 2. Como agora a gente ta fazendo
    iterações, o que a gente quer agora é velocidade, então veja aí o que
    fica mais facil e rapido pra ti implementar o quanto antes."

KEY DECISIONS taken from this conversation:

    1. Failure mode classification (Opção 2) is the primary qualitative
       evaluation axis for Iteration 1.

    2. Side-by-side visual inspection (Opção 1) is deferred to Iteration 2
       if time permits.

    3. The "cenário possível vs impossível" framing is what motivates
       CheckDiscontinuousGround (no continuous floor means no possible
       scenario). Future iterations should add a global connectivity check
       (can the player traverse the chunk from left to right?).

    4. Speed of iteration is the current optimization target. Code structure
       should favor extensibility over micro-optimization.

PART 6: WHAT REMAINS FOR ITERATION 1
================================================================================

Iteration 1 evaluation work is COMPLETE. The neural network pipeline still
requires three components before training can run:

    Component                                Status            Estimated effort
    ---------------------------------------  ----------------  ----------------
    UnetBaseline class composition           Not started       1 day
    Conditional Flow Matching training loop  Not started       2 days
    Euler ODE solver inference path          Not started       1 day
    First training run + metric collection   Not started       2 days
    TCC Chapter 4 first draft                Not started       3 days

The UnetBaseline is the next critical-path item: it composes the existing
SinusoidalTimeEmbedding, ResidualConvBlock, DownsampleBlock, and Upsample-
Block into a complete encoder-decoder network with skip connections that
takes (x, t) and returns a predicted velocity field of the same shape as x.

After UnetBaseline is built, the training loop and Euler solver can be
implemented in parallel since they share no dependencies. Once both exist,
the first training run can produce generated maps that the FailureMode-
Analyzer evaluates immediately.
