1. PROJECT OVERVIEW
================================================================================

Title: Procedural Generation of Game Maps as a Constraint Satisfaction Problem:
       An Euler-based Conditional Flow Matching Approach

The TCC trains a Conditional Flow Matching (CFM) neural network to generate
2D tile-based game maps. The model learns implicit spatial constraints (tile
adjacency rules, biome coherence, path connectivity) from a dataset of existing
valid maps, then generates new maps that satisfy those constraints.

The approach replaces manually-defined constraint rules (as used by Wave
Function Collapse) with learned constraints from data, and replaces the slow
iterative sampling of Diffusion Models with efficient Euler ODE integration.

4.4 TRAINING DATA GENERATION

    Sliding window of 28 tiles wide (one Mario screen) by 14 tiles tall
    (full level height), stride 1 tile horizontally.

    From 15 levels: 2518 training chunks extracted.
    Each chunk is a one-hot tensor of shape (C=14, H=14, W=28).
    Full batch tensor shape: (N=2518, C=14, H=14, W=28).

5.4 ONE-HOT ENCODING

    Each tile position is represented as a 14-element vector where exactly
    one element is 1.0 and all others are 0.0. The index of the 1.0 element
    corresponds to the TileTypeEnum integer value.

    Example: a Solid tile at position (x=5, y=13) sets:
        tensor[2, 13, 5] = 1.0  (channel 2 = Solid)
        all other channels at (13, 5) = 0.0

    The reverse operation (FromOneHotTensor) takes argmax along the channel
    dimension to recover the discrete tile type per position.

9. KEY DECISIONS AND RATIONALE
================================================================================

9.1 DATASET: VGLC SUPER MARIO BROS (not Terraria, not Super Metroid)

    Reason: VGLC is free, pre-processed, and ready to use immediately.
    Published research (Volz et al. 2018, GECCO) trained a GAN on this
    exact dataset, providing a direct baseline for comparison. Super Metroid
    rooms were not yet extracted. Terraria maps had no clear validity rules.

9.2 C# WITH TORCHSHARP (not Python with PyTorch)

    Reason: Integrates with the company's existing C# ML codebase
    (kcg-ml-csharp). The company supports the TCC and provides GPU access.
    TorchSharp provides the same operations as PyTorch.

9.3 NO XLIB DEPENDENCIES

    Reason: The TCC must be deliverable as a standalone repository that
    the UFSC banca can clone and build. kcg-xlib is proprietary company
    code that cannot be redistributed. The only xlib usage (LibLog) was
    replaced with Console.WriteLine.

9.4 PURE STATE TILEMAP (no GetTile/SetTile methods)

    Reason: kcg-ml-csharp standards require state-action separation.
    TileMap is a pure data holder (Width, Height, Tiles[]). All callers
    access the Tiles array directly: map.Tiles[y * map.Width + x].

9.5 ERROR=0 IN TILETYPE ENUM (not None, not Unknown)

    Reason: standard-enum-zero-is-error.txt mandates value 0 represents
    an error state. C# initializes uninitialized enum fields to 0. If 0
    were a valid tile type, uninitialized tiles would silently appear as
    valid data instead of triggering an error.
